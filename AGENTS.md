- Droits d'écriture métier : politiques RLS RESTRICTIVE « RBAC write » via can_write_module(uid, module) ; pourquoi : les permissions RBAC doivent être appliquées côté serveur, pas seulement dans l'interface.
- Référentiels pétroliers : petroleum_products / depots / nozzles scoupés tenant+country, product_id additif à côté de product_type texte ; pourquoi : migrer sans casser les écrans qui lisent encore super/gasoil.
- Stock : registre immuable stock_movements (trigger stock_movement_before) + vue stock_levels (security_invoker) ; pourquoi : aucune modification silencieuse, toute correction = mouvement tracé et validé.
- Clôture journalière : daily_closures + closure_sales/payments verrouillées hors brouillon, transitions uniquement via closure_transition (crée les stock_movements sale / adjustment_in à la validation / réouverture) ; pourquoi : pas de modification silencieuse d'une clôture validée ni du stock.
- Approvisionnement : supply_requests + supply_request_events immuable, étapes uniquement via supply_transition (réception validée = stock_movements entry) ; pourquoi : chaîne tracée, aucune mise en stock sans jauges validées.
- Command Center : src/components/command/CommandCenter.tsx lit uniquement via RLS en filtrant tenant actif + pays de l'espace de travail (ventes = clôtures non rejetées, sinon index_entries) ; pourquoi : aucun KPI hors périmètre autorisé.
- Réconciliation : reconciliations + reconciliation_events immuable, calcul uniquement via reconcile_station_day, suivi via reconciliation_action, seuils reconciliation_tolerances (pays > produit) ; pourquoi : résultats reproductibles et historique complet des décisions du contrôleur.
- Anti-fraude : fraud_rules (config tenant+pays, défauts via fraud_rule_defaults) + fraud_alerts (dédoublonnées par fingerprint, jamais supprimées) + fraud_alert_events immuable ; détection uniquement via run_fraud_scan (règles SQL explicables), workflow via fraud_alert_action ; Risk Score calculé côté écran à partir des alertes (barème affiché) ; pourquoi : aucune logique opaque, chaque alerte cite sa règle et son seuil.
- Langue d'interface : LanguageProvider conserve le choix FR/EN par utilisateur, avec langue par défaut du client et libellés français comme source ; pourquoi : éviter qu'un changement de client réinitialise une préférence explicite.
- Fuel Cards: isolated tenant/country card accounts use a server-authorized action RPC, immutable purchase and limit journals, and read-only scoped tables; why: balances, limits, and restrictions must never depend on browser checks.
- B2B CRM: scoped immutable contractual terms, consumption and invoice journals are written through a server-authorized action RPC; a credit guard combines B2B purchases and postpaid card balances, so neither channel can bypass the shared credit policy.
- Logistics: scoped logistics_* referentials (no deletes), trips advanced only via logistics_trip_action with immutable trip events and GPS positions, alerts computed by the logistics_alerts view; why: provider-agnostic GPS and traceable, explainable transport alerts.
- Logistics loading: trip loading plans live in logistics_trip_loads, written only via logistics_set_loads (full capacity, one product+destination per compartment, mono/mixed mode) and frozen once loaded; why: load conformity is enforced server-side and stays traceable.
- Logistics menu: single "logistique_avancee" tab hosts carriers, fleet (legacy trucks absorbed), supply requests, trips, map and alerts in process order; why: one coherent logistics workflow.
- Logistics delivery: per-site check-in via logistics_confirm_site writes immutable logistics_load_deliveries (≤ compartment load); the RPC auto-closes the trip to delivered after the last site (event deliver_auto), with manual "deliver" kept as fallback; delivered still requires every load line checked in; why: no global delivery without site-by-site proof.
- Assets & Maintenance: maintenance_assets/plans/work_orders/parts (no deletes) with immutable maintenance_events; server triggers number work orders, compute downtime/parts cost, sync asset status and reschedule plans; why: traceable maintenance with costs that cannot be edited from the browser.
- HSE & Compliance: scoped hse_* tables (no deletes, immutable hse_history); statuses change only via hse_action; hse_scope_guard/hse_agent_guard reject cross-tenant/country links and inactive agents; hse_agents writable only with hse.manage; Compliance Score in src/lib/hse.ts with visible weights; why: traceable, per-country, server-enforced compliance.
- BI & IA : calculs uniquement via src/lib/metrics et src/lib/assistant (données useBiDataset, tenant actif + pays autorisés) ; les fonctions IA ne reçoivent que ces faits, n'écrivent rien, et lumatek-assistant journalise chaque question ; pourquoi : un seul calcul métier, traçable, sans données hors périmètre.
- Forecasts: replaceable read-only models in src/lib/metrics/forecasting.ts use scoped BI data, completed observed days and leakage-free retrospective holdouts; critical query errors stop projections, and missing data stays unknown; why: forecasts must be reproducible, uncertain and safely comparable to actuals.
- API Hub: read-only REST `api-v1` edge function authenticates hashed tenant API keys (created/rotated/revoked only via platform-admin RPCs), then enforces key scopes, license mode, active+allowed countries and per-country module flags, logs every call and rate-limits from the log; webhooks are enqueued by DB triggers and sent HMAC-signed by `api-webhooks`; why: integrations obey the same tenant/country/license rules as the app.
- Integrations: scoped integration_connectors changed via integration_action; credentials AES-GCM encrypted by integration-hub into a service-role-only table; idempotent jobs with backoff and immutable logs; providers via driver registry; why: no hardcoded vendor, no browser secret. Scheduling via set_schedule; hourly pg_cron calls integration-hub 'tick' with a secret from service-role-only integration_scheduler_config.
