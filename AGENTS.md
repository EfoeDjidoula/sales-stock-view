- Droits d'écriture métier : politiques RLS RESTRICTIVE « RBAC write » via can_write_module(uid, module) ; pourquoi : les permissions RBAC doivent être appliquées côté serveur, pas seulement dans l'interface.
- Référentiels pétroliers : petroleum_products / depots / nozzles scoupés tenant+country, product_id additif à côté de product_type texte ; pourquoi : migrer sans casser les écrans qui lisent encore super/gasoil.
- Stock : registre immuable stock_movements (trigger stock_movement_before) + vue stock_levels (security_invoker) ; pourquoi : aucune modification silencieuse, toute correction = mouvement tracé et validé.
- Clôture journalière : daily_closures + closure_sales/payments verrouillées hors brouillon, transitions uniquement via closure_transition (crée les stock_movements sale / adjustment_in à la validation / réouverture) ; pourquoi : pas de modification silencieuse d'une clôture validée ni du stock.
- Approvisionnement : supply_requests + supply_request_events immuable, étapes uniquement via supply_transition (réception validée = stock_movements entry) ; pourquoi : chaîne tracée, aucune mise en stock sans jauges validées.
- Command Center : src/components/command/CommandCenter.tsx lit uniquement via RLS en filtrant tenant actif + pays de l'espace de travail (ventes = clôtures non rejetées, sinon index_entries) ; pourquoi : aucun KPI hors périmètre autorisé.
- Réconciliation : reconciliations + reconciliation_events immuable, calcul uniquement via reconcile_station_day, suivi via reconciliation_action, seuils reconciliation_tolerances (pays > produit) ; pourquoi : résultats reproductibles et historique complet des décisions du contrôleur.
- Anti-fraude : fraud_rules (config tenant+pays, défauts via fraud_rule_defaults) + fraud_alerts (dédoublonnées par fingerprint, jamais supprimées) + fraud_alert_events immuable ; détection uniquement via run_fraud_scan (règles SQL explicables), workflow via fraud_alert_action ; Risk Score calculé côté écran à partir des alertes (barème affiché) ; pourquoi : aucune logique opaque, chaque alerte cite sa règle et son seuil.
- Langue d'interface : LanguageProvider conserve le choix FR/EN par utilisateur (défaut du client, libellés français comme source) ; en anglais, src/lib/domTranslator.ts traduit le texte affiché sur place via translations.generated.ts (regénéré par scripts/i18n) ; pourquoi : couvrir tous les écrans sans réécrire chaque libellé ni réinitialiser une préférence explicite.
- Fuel Cards: isolated tenant/country card accounts use a server-authorized action RPC, immutable purchase and limit journals, and read-only scoped tables; why: balances, limits, and restrictions must never depend on browser checks.
- B2B CRM: scoped immutable contractual terms, consumption and invoice journals are written through a server-authorized action RPC; a credit guard combines B2B purchases and postpaid card balances, so neither channel can bypass the shared credit policy.
- Logistics: scoped logistics_* referentials (no deletes), trips advanced only via logistics_trip_action with immutable trip events and GPS positions, alerts computed by the logistics_alerts view; why: provider-agnostic GPS and traceable, explainable transport alerts.
- Logistics loading: trip loading plans live in logistics_trip_loads, written only via logistics_set_loads (full capacity, one product+destination per compartment, mono/mixed mode) and frozen once loaded; why: load conformity is enforced server-side and stays traceable.
- Logistics menu: single "logistique_avancee" tab hosts carriers, fleet (legacy trucks absorbed), supply requests, trips, map and alerts in process order; why: one coherent logistics workflow.
- Logistics delivery: logistics_confirm_site writes immutable logistics_load_deliveries (≤ compartment load), auto-delivers after the last site; why: site-by-site proof.
- Maintenance: maintenance_* tables (no deletes, immutable events); triggers number work orders, compute downtime/costs, sync asset status, reschedule plans; why: costs not editable from the browser.
- HSE: scoped hse_* tables (no deletes, immutable hse_history), statuses only via hse_action, guards reject cross-scope links/inactive agents, hse_agents needs hse.manage; score weights in src/lib/hse.ts; why: traceable server-enforced compliance.
- BI & IA : calculs uniquement via src/lib/metrics et src/lib/assistant (données useBiDataset, tenant actif + pays autorisés) ; les fonctions IA ne reçoivent que ces faits, n'écrivent rien, et lumatek-assistant journalise chaque question ; pourquoi : un seul calcul métier, traçable, sans données hors périmètre.
- Forecasts: read-only models in src/lib/metrics/forecasting.ts (scoped data, completed days, leakage-free holdouts; query errors stop projections, missing data stays unknown); why: reproducible, comparable to actuals.
- API Hub: read-only `api-v1` authenticates hashed tenant keys (managed by platform-admin RPCs), enforces scopes, licence, countries and module flags, logs and rate-limits calls; DB triggers enqueue webhooks signed (HMAC) by `api-webhooks`; why: integrations obey app rules.
- Integrations: scoped connectors via integration_action; credentials AES-GCM encrypted by integration-hub in a service-role-only table; idempotent jobs, backoff, immutable logs, driver registry; hourly pg_cron 'tick' scheduling via set_schedule; why: no hardcoded vendor or browser secret.
- Workflows: requests change only via workflow_action (immutable events, delegations, scope/licence/role checks, no self-approval); final approval executes the operation once via DB trigger (stock movement / new b2b_terms); why: no RBAC bypass, atomic execution.
- Login CAPTCHA: Turnstile token checked by `verify-turnstile` before sign-in; why: secret stays server-side.
- PDF: jsPDF via src/lib/pdf; why: it strips fr-FR spaces shown as "/".
- Index model: retour_cuve, index_tank_readings and sales/versement variances are recomputed by DB triggers; formulas in src/lib/indexModel.ts; why: no browser-side tampering.
- Navigation: sections grouped only in src/lib/navigation.ts, rendered by AppSidebar; badges = read-only scoped counts (useNavBadges); why: one menu definition.
- File & export safety: stored files open via authenticated download (src/lib/storageFiles.ts), never signed URLs; CSV cells go through src/lib/csv.ts; integration-hub outbound calls pass netguard.ts (public HTTPS only, no redirects); why: no bearer links, formula injection or internal-network access.
- Identity helpers (has_role, get_user_role, get_user_tenant) only answer for self, same-tenant admins/colleagues or platform admins; internal-only helpers have EXECUTE revoked from app roles; why: no cross-user/tenant lookups.
- Index validation: index_entries start 'pre_enregistre'; only validate_index_entry / reject_index_entry (N+1, no self-decision, strict chronological order, mandatory reject reason) change status, logged in immutable index_entry_events; validation locks the entry, posts sale + inventory stock_movements and generates the day's validated daily_closure (source 'index', never overwriting a submitted/validated one, no double stock sale); editing a rejected entry returns it to 'pre_enregistre'; why: one traceable path from station input to official stock, closures and KPIs.
- Dépotages: the only source is validated logistics receptions (supply_requests 'received'); the legacy depotages table is read-only history; why: index entry and stock read one reception record.
- Tenant logo/favicon: local files (drag-drop or picker) are signature-checked and redrawn as compact PNG data URLs by src/lib/brandImage.ts and stored in tenants.logo_url/favicon_url (links still accepted); why: the workspace blocks public buckets and redrawing strips active content such as SVG scripts.
- B2B client portal: b2b_portal_users memberships make get_user_tenant return NULL (no tenant-wide RLS access); clients read only via b2b_portal_overview and act via b2b_portal_action, staff manage via b2b_portal_staff_action and the create-portal-user function; why: a client login can never reach tenant data through ordinary table policies.
- Offline: vite-plugin-pwa registered only by src/lib/pwa.ts (never in dev/preview/iframe), NetworkFirst navigations with precached shell fallback; React Query cache persisted to IndexedDB (cleared at sign-in/out); offline writes go through src/lib/offlineQueue.ts and replay the same server paths; why: field entry without network while keeping server rules authoritative.
- Report e-mails: send-report-email sends the displayed report only to the caller's own address (reports.view), table capped and escaped, link back to the app instead of attachments; why: app emails are one-recipient, user-triggered.
