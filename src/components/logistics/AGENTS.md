- Logistics loading: trip loading plans live in logistics_trip_loads, written only via logistics_set_loads (full capacity, one product+destination per compartment, mono/mixed mode) and frozen once loaded; why: load conformity is enforced server-side and stays traceable.
- Logistics delivery: logistics_confirm_site writes immutable logistics_load_deliveries (≤ compartment load), auto-delivers after the last site; why: site-by-site proof.
- Logistics variance fixes: delivered trips are corrected only via logistics_variance_action (supplies.validate): 'rectify' inserts immutable deliveries for unconfirmed compartments (or sets the total for plan-less trips), 'justify' records a categorized reason; both are trip events, and logistics_alerts hides a quantity variance only while a justification is newer than the last delivery change; why: no silent edit, confirmed site proof stays frozen.
