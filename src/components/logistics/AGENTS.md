- Logistics loading: trip loading plans live in logistics_trip_loads, written only via logistics_set_loads (full capacity, one product+destination per compartment, mono/mixed mode) and frozen once loaded; why: load conformity is enforced server-side and stays traceable.
- Logistics delivery: logistics_confirm_site writes immutable logistics_load_deliveries (≤ compartment load), auto-delivers after the last site; why: site-by-site proof.
- Logistics variance fixes: delivered trips are corrected only via logistics_variance_action (supplies.validate): 'rectify' inserts immutable deliveries for unconfirmed compartments (or sets the total for plan-less trips), 'justify' records a categorized reason; both are trip events, and logistics_alerts hides a quantity variance only while a justification is newer than the last delivery change; why: no silent edit, confirmed site proof stays frozen.
- Three-stock balance: src/lib/threeStocks.ts (tested) splits ordered-not-lifted / in-transit (BL) / received (booked at BL, gauge = truck variance) from supply_requests, read-only; why: the three stocks never mix.
- Depot supply (phase 1): pro-formas, purchase orders and payment status live in depot_proformas/lines/purchase_orders, written only via depot_supply_action with immutable depot_purchase_order_events; availability = authorized (paid/credit PO only) − lifted, computed in src/lib/depotSupply.ts (tested); why: a pro-forma alone never releases stock.
- Lifting orders (phase 2): BE live in depot_lifting_orders/lines/events, written only via depot_supply_action (create/sign/cancel); each BE owns one logistics_trip whose loads only depot_supply_action may set; balance = paid/credit PO − lifted (signed) − reserved (drafted); trucks/drivers pass logistics_vehicle_availability / logistics_driver_availability (open trip, status, expired or missing documents) server-side; trips cannot progress before signature and are cancelled only through the BE; why: no lifting beyond the paid balance or with an unfit truck.
- Loading tracking (phase 3): src/components/logistics/LoadingTrackingTab.tsx derives 7 operational stages via src/lib/loadingTracking.ts (tested) from trips, loads, deliveries and open variance alerts; read-only, history from immutable logistics_trip_events; why: no new write path.
- Delivery notes (phase 4): logistics_delivery_notes are frozen per-destination BL snapshots; designated users sign via logistics_bl_action in shipper→carrier→consignee order (immutable signatures/events); why: authenticated 3-party proof without stock writes.
- Compartment discharges (phase 5): logistics_discharges rows are written only via logistics_discharge (supplies.validate, confirmed site delivery, tank of the delivered station and same product, immutable); stock entry booked at BL volume only for trips without a supply_request (else the supply reception books it), gauge variance stays separate; why: no double stock entry, traceable tank allocation.
- LO/DN split (phase 6): src/components/logistics/LiftingAllocationTab.tsx compares lifted (BE lines) vs allocated (trip loads per destination/BL) vs delivered via src/lib/liftingAllocation.ts (tested); read-only; why: loads are already server-guarded, the split only exposes gaps.
- Station provision (phase 7): StationProvisionTab values signed-BE loaded station volumes (BL) at the country pump price in force on the delivery date (price_structures via useCountryPrices) using src/lib/stationProvision.ts (tested); read-only + exceljs export; why: same BL basis as stock, no new write path.
- Logistics dashboard (phase 8): LogisticsDashboardTab builds stock sheets (ordered → lifted → received), loss by carrier/truck/driver, rotation delays and order execution via src/lib/logisticsKpis.ts (tested); read-only; why: KPIs reuse the same BL/discharge records, no new write path.
- B2B portal delivery notes: clients read their BL via b2b_portal_delivery_notes and sign as consignee through logistics_bl_action; why: same signature rules for staff and clients.
- Fleet: one FleetTab creates vehicle + towed unit (tractor→default_trailer_id) + compartments in one form, default_driver_id pre-fills lifting orders; kinds in src/lib/fleet.ts (tested); why: one place to configure a truck.
